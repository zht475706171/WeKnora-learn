# 16 · 保护区间机制详解(7 种保护模式 + 数据结构 + 怎么找)

> 用户问:LaTeX/表格/代码/图片/链接区间内是怎么判断和标识的?是体检时记录行号?数据结构是什么?分别存什么?

---

## 先破一个误解:不是体检时记录的

**重要**:保护区间**不是**体检(ProfileDocument)时记录的!

- 体检只统计**结构信号**(标题、章节标记、行数等),**不记录保护区间**
- 保护区间是**切分时(SplitText / Tier 3)实时计算的**,每次切分重新扫一遍

**为什么分开**:
- 体检的输出 `DocProfile` 用来**选策略**(Tier 1/2/3),不需要知道保护区间在哪
- 保护区间是**切分时**才需要的,每次切分实时算,因为切分可能在不同上下文(比如 Tier 1 二次切 section,section 内的保护区间跟全文的不一样)

---

## 数据结构:就一个 `span`

```go
type span struct {
    start, end int
}
```

**两个字段**:`start` 和 `end`,**字节偏移**(byte offset,不是 rune,不是行号)。

```go
[]span  // 一个切片,存所有保护区间
```

**没有按类型分**:`[]span` 里混着 LaTeX/图片/链接/表格/代码/行内代码,**不区分类型**,只知道"这段是保护的,不能切"。

**为什么不分类型**:切分逻辑只关心"这里不能切",**不关心为什么不能切**。分类型是浪费内存。

---

## 7 种保护模式(7 个正则)

```go
var protectedPatterns = []*regexp.Regexp{
    `(?s)\$\$.*?\$\$`,                    // 1. LaTeX 块公式
    `!\[[^\]]*\]\([^)]+\)`,                // 2. Markdown 图片
    `\[[^\]]*\]\([^)]+\)`,                 // 3. Markdown 链接
    `(?m)...|...|...\n|---|---|...`,       // 4. 表格头+分隔行
    `(?m)...|...|...\n`,                   // 5. 表格行
    `(?s)```(?:\w+)?[\r\n].*?```,          // 6. 代码块
    "`[^`\r\n]+`",                         // 7. 行内代码
}
```

### 1. LaTeX 块公式 `$$...$$`
```
$$E = mc^2$$
$$\int_0^1 x^2 dx$$
```
`(?s)` 让 `.` 匹配换行,`.*?` 非贪婪(防两个公式间的内容被当成一个公式)。

### 2. Markdown 图片 `![alt](url)`
```
![示意图](images/diagram.png)
![架构图](https://example.com/arch.png)
```
`[^\]]*` 匹配 alt 文本(不能有 `]`),`[^)]+` 匹配 URL(不能有 `)`)。

### 3. Markdown 链接 `[text](url)`
```
[文档](docs/readme.md)
[官网](https://example.com)
```
跟图片一样的结构,只是少了前面的 `!`。

### 4. 表格头 + 分隔行
```
| 列1 | 列2 |
| --- | --- |
```
匹配"表头行 + 分隔行"的组合,这是表格的标志。

### 5. 表格行
```
| 数据1 | 数据2 |
```
匹配单个表格行(管道符 `|` 分隔)。

### 6. 代码块 ` ```...``` `
```
```go
func main() { ... }
```
```
`(?s)` 多行匹配,`(?:\w+)?` 匹配可选的语言标识(如 `go` `python`)。

### 7. 行内代码 `` `code` ``
```
使用 `fmt.Println` 打印。
```
单行内的代码,不能跨行(`[^`\r\n]` 排除换行符)。

## 怎么找的(protectedSpans 函数)

```go
func protectedSpans(text string) []span {
    var all []match
    // 1. 用 7 个正则找所有匹配
    for _, pat := range protectedPatterns {
        locs := pat.FindAllStringIndex(text, -1)
        for _, loc := range locs {
            if loc[1]-loc[0] > 0 {
                all = append(all, match{loc[0], loc[1]})
            }
        }
    }
    if len(all) == 0 { return nil }

    // 2. 排序:按 start 升序,同 start 按长度降序(长的优先)
    ...

    // 3. 去重:去掉重叠的(保留先出现的)
    var result []span
    lastEnd := 0
    for _, m := range all {
        if m.start >= lastEnd {
            result = append(result, span{m.start, m.end})
            lastEnd = m.end
        }
    }
    return result
}
```

**3 步**:

### Step 1:7 个正则找所有匹配

每个正则独立扫全文,找到所有匹配区间 `[start, end)`(字节偏移),全部塞进 `all` 列表。

**例子**:文档有 2 个公式 + 1 个代码块 + 3 个链接,`all` 有 6 个 match。

### Step 2:排序

按 **start 升序**,同 start 按**长度降序**(长的优先)。

**为什么长度降序**:如果两个匹配同位置开始(比如代码块和行内代码都从位置 100 开始),**长的优先**(代码块包含行内代码,保留代码块)。

### Step 3:去重(去重叠)

```go
lastEnd := 0
for _, m := range all {
    if m.start >= lastEnd {
        result = append(result, span{m.start, m.end})
        lastEnd = m.end
    }
    // 否则:这个 match 跟前面的重叠,丢弃
}
```

**规则**:当前 match 的 start 必须 ≥ 上一个保留的 end,否则丢弃(跟前面重叠了)。

## 用字节偏移,不是行号,不是 rune 偏移

```go
locs := pat.FindAllStringIndex(text, -1)
// locs 是字节偏移
```

**为什么用字节**:
- Go 的 `regexp` 包返回的是**字节偏移**(不是 rune)
- 正则匹配按字节工作,效率高
- 转换到 rune 是额外开销

**但下游用 rune 偏移**(因为 chunk 的 Start/End 是 rune 偏移),所以有个转换函数:

```go
func protectedSpansRune(text string, byteSpans []span) []span {
    // 字节偏移 → rune 偏移
}
```

**转换时机**:
- `protectedSpans` 返回**字节偏移**的 span
- `protectedSpansRune` 转成**rune 偏移**的 span
- 下游(mergeUnits、computeOverlap、Tier 2 的 dropBoundsInsideSpans)都用 rune 偏移

## 各层怎么用保护区间

### Tier 3(SplitText)—— buildUnitsWithProtection

```go
// Step 1:找保护区间(字节偏移)
protected := protectedSpans(text)

// Step 2:切+保原子
units := buildUnitsWithProtection(text, protected, separators, chunkSize)
```

`buildUnitsWithProtection` 遍历保护区间:
- **保护区间之间的普通文本**:用 `splitBySeparators` 切
- **保护区间本身**:作为单个原子 unit,不切
- **保护单元超 7500 字**:才硬切(换行/空格对齐)

### Tier 2 —— dropBoundsInsideSpans

```go
if prot := protectedSpansRune(text, protectedSpans(text)); len(prot) > 0 {
    bounds = dropBoundsInsideSpans(bounds, prot)
}
```

Tier 2 找完切点后,把落在保护区间**严格内部**的切点丢弃,边缘的保留。

### Tier 3 overlap —— findSemanticOverlapBoundary

```go
protected := protectedSpansRune(text, protectedSpans(text))
insideProtected := func(pos int) bool {
    for _, p := range protected {
        if pos >= p.start && pos < p.end { return true }
    }
    return false
}
// 边界落在保护区间内 → 不合格
```

overlap 找边界时,排除保护区间内的位置,防 overlap 切在表格/代码中间。

## 不是体检时记录的 —— 重复计算问题

**你可能会问**:每次切分都重新算保护区间,不是浪费吗?

**答案**:是有点浪费,但**没必要优化**:
- 保护区间计算是 O(N)(正则扫一遍)
- 切分本身也是 O(N)
- 加起来还是 O(N),不是瓶颈
- 优化(把保护区间存进 DocProfile)会增加内存 + 复杂度,收益小

**例外**:Tier 1 二次切 section 时,section 是原文的一段,**保护区间要重新算**(因为 section 内的保护区间跟全文的不一样)。这种情况下必须实时算。

## 你应该带走的 6 件事

1. **保护区间不是体检时记录的**:是切分时实时算的,每次切分重新扫一遍。体检只统计结构信号,不管保护区间。

2. **数据结构就一个 `span {start, end}`**:两个字段,字节偏移。`[]span` 存所有保护区间,**不分类型**(LaTeX/图片/链接/表格/代码混在一起,因为切分只关心"不能切",不关心为什么)。

3. **7 个正则匹配 7 种保护模式**:LaTeX `$$`、图片 `![]()`、链接 `[]()`、表格头+分隔行、表格行、代码块 ` ``` `、行内代码 `` ` ``。

4. **3 步找保护区间**:7 个正则找所有匹配 → 按 start 升序排序(同 start 长的优先)→ 去重叠(保留先出现的)。

5. **用字节偏移,不是行号/rune**:正则匹配返回字节偏移(快),下游用 rune 偏移(正确,中文 1 字 = 1 rune 但可能 3 字节),`protectedSpansRune` 做转换。

6. **3 层都用保护区间**:T3 的 `buildUnitsWithProtection`(保护单元原子化)、T2 的 `dropBoundsInsideSpans`(丢弃保护区间内的切点)、T3 overlap 的 `insideProtected`(边界不在保护区间内)。
