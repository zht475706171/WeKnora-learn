# 01 · WeKnora 最外层架构(大白话版)

> 学习目标:不看代码,光看目录和 README,先把"WeKnora 是干嘛的、有哪几大块、它们怎么配合"这件事在脑子里搭个骨架。后面再一层层下钻。

---

## 一句话总结

**WeKnora 是腾讯开源的"企业级知识问答+智能推理框架"**。
你把一堆文档塞进去,它帮你做成一个能问、能答、能推理、能自己长知识库的"私有 ChatGPT+Wiki"。

---

## 它到底能干啥(用大白话)

设想你是公司 IT,老板丢给你三件事:
1. 把全公司的 PDF / Word / 飞书文档 / Notion 全收集起来,变成一个能搜的东西
2. 让员工能直接对话提问,系统自己去找文档回答,还必须给引用
3. 不能光会背文档,还得会"想":需要查别的工具就去查,需要联网就联网,需要写步骤就写步骤

WeKnora 就是干这三件事的。它有三种"主玩法":

| 模式 | 类比 | 适合场景 |
|------|------|---------|
| **RAG 快速问答** | 像"带引用的开卷考":你问→它去文档里找段落→喂给大模型→回你 | 平时查知识,90% 场景 |
| **ReAct Agent** | 像"会自己安排步骤的实习生":会判断"先查文档再调工具再联网",一步步推 | 复杂任务,比如"帮我查下季度销售数据并对比去年" |
| **Wiki 模式** | 像"AI 自己写维基百科":Agent 把一堆原始文档消化成结构化、互相链接的 Markdown 页面+知识图谱,人还能改、能回滚 | 把乱七八糟文档整理成体系 |

└── config/ dataset/ examples/ testdata/ tests/  # 配置/样例/测试

### 大模块职责一句话版

| 模块 | 干啥的 | 啥语言 |
|------|--------|--------|
| **cmd/** | 程序启动入口,里面 `cmd/server` 是后端服务入口 | Go |
| **internal/** | 后端所有业务逻辑,90% 的代码在这 | Go |
| **frontend/** | 浏览器里的 Web 界面 | Vue3 + TS |

| **cli/** | 命令行工具 `weknora`,管理员/脚本化用 | Go |

## 一条数据流(把模块串起来,看它们怎么配合)

这是理解 WeKnora 最关键的一条主线。下面这段你读懂了,整个项目的骨架就立住了。

### 场景:用户上传一份 PDF,然后提问"公司报销流程是什么?"

```
[用户浏览器]
   │  ① 上传 PDF
   ▼
[frontend]  ← 发请求
   │
   ▼
[cmd/server → internal/router]  ← 接收 API
   │
   ▼
[internal/handler]  ← 处理上传
   │
   ├──→ [docreader]  ② 把 PDF 解析成文本块(Python gRPC)
   │       └── 返回结构化文本块(chunks)
   │
   ├──→ [internal/Embedding]  ③ 文本块 → 向量(调模型厂商)
   │
   ├──→ [internal/database/pgvector]  ④ 向量+原文存进 PostgreSQL
   │
   └──→ [internal/runtime]  ⑤ 入队异步任务(分阶段 Worker 池)

  ---  下面是提问阶段  ---

[用户] "公司报销流程是什么?"
   ▼
[router → handler]
   │
   ▼
[internal/agent]  ⑥ Agent 循环:
   │     思考1: "这是知识库问题,先检索"
   │     动作1: 检索知识库(向量召回 + BM25 关键词召回 + Rerank 重排)
   │     思考2: "拿到 5 个相关段落,够答了"
   │     动作2: 调 LLM 生成答案(带引用)
   │
   ├──→ [internal/modelcontext]  控制塞给 LLM 的上下文长度
   ├──→ [internal/models]       调 OpenAI/DeepSeek 等
   ├──→ [internal/tracing]      全程打 Langfuse 追踪
   ▼
[前端流式渲染答案 + 引用浮层]
```

### 这条流里你能记住的 5 个关键词

1. **文档解析**(docreader):杂七杂八的格式 → 干净文本块
2. **向量化**(Embedding):文本块 → 数字向量(用来"按意思搜")
3. **混合检索**(向量 + BM25 + Rerank):把最相关的段落捞出来
4. **Agent 循环**(ReAct):让 LLM 自己决定下一步干啥
5. **异步任务**(runtime/Worker 池):重活排队干,不卡主进程

## 技术栈一览

| 层 | 技术 |
|----|------|
| 后端 | **Go 1.26**(主),程序入口在 `cmd/`,业务在 `internal/` |
| 文档解析 | **Python**(`docreader`,单独服务,通过 gRPC 跟后端通信) |
| MCP | **Python**(`mcp-server`,独立 PyPI 包 `tencent-weknora-mcp`) |
| 前端 | **Vue3 + TypeScript + Vite**(`frontend/`) |
| 数据库 | **PostgreSQL + pgvector**(主力,既存业务数据又存向量) |
| 对象存储 | 本地 / COS / OSS / S3 / MinIO 等,可换 |
| 向量库 | pgvector / ES / Milvus / Qdrant / Weaviate 等,可换 |
| LLM | OpenAI / DeepSeek / Qwen / 智谱 / 混元 / Gemini / Ollama 等 |
| 部署 | Docker Compose / Kubernetes(Helm) |

> 关键点:**模块化、可替换**。模型、向量库、存储、Embedding 都能换。这是 WeKnora 主打"企业级私有化"的核心。

---

## 这一节你应该带走的 3 件事

1. **WeKnora = 私有化部署的企业级 RAG+Agent+Wiki 框架**,核心语言 Go,带 Python 解析服务。
2. **顶层 6 大模块**:`cmd`(入口)/`internal`(后端大脑)/`frontend`(界面)/`docreader`(解析)/`mcp-server`(对外)/`cli`(命令行)。
3. **核心数据流**:上传→解析→切块→向量化→入库;提问→Agent 循环→混合检索→LLM 生成→带引用回答。
