# 18 · 保护机制 7500 硬切详解(切成什么?是不是单独一个 chunk?)

> 用户问:超过 7500 是怎么切割的?切成什么样?是单独进一个 chunk 吗?

---

## 一句话

> **保护内容(LaTeX/表格/代码/链接/图片)正常是原子 unit,不切。但超过 7500 字就硬切:按 7500 一段切,切点往前回退 200 字找 `\n` 或空格对齐。切出来的段不一定单独成 chunk —— 大段(接近 7500)必然单独一个 chunk,尾巴那段短的可能跟下个 unit 合到 ~512。**

---

## 7500 出现在 2 个地方

### 地方 1:`buildUnitsWithProtection`(splitter.go:308)—— 保护内容本身超 7500

```go
const maxProtectedSize = 7500
if protRuneLen > maxProtectedSize {
    runes := []rune(protText)
    offset := 0
    for offset < len(runes) {
        chunkEnd := offset + maxProtectedSize  // 先按 7500 切
        if chunkEnd > len(runes) {
            chunkEnd = len(runes)
        } else {
            // 往前回退最多 200 字,找换行或空格
            for i := chunkEnd - 1; i > offset && i > chunkEnd-200; i-- {
                if runes[i] == '\n' || runes[i] == ' ' {
                    chunkEnd = i + 1
                    break
                }
            }
        }
        chunkText := string(runes[offset:chunkEnd])
        units = append(units, splitUnit{...})  // 切出来的每段当一个 unit
        offset = chunkEnd
    }
}
```

**切出来的是 unit**,后续走 mergeUnits 装箱。

### 地方 2:`mergeUnits`(splitter.go:401)—— 单个 unit 超 7500(兜底)

```go
const absoluteMaxSize = 7500
if uLen > absoluteMaxSize {
    // 先把当前 chunk 封口
    if len(current) > 0 {
        chunks = append(chunks, buildChunk(current, len(chunks)))
        current = nil
        curLen = 0
    }
    // 把这个超大 unit 单独切
    runes := []rune(u.text)
    offset := 0
    for offset < len(runes) {
        chunkEnd := offset + absoluteMaxSize
        // 同样的回退 200 找 \n 或空格
        chunks = append(chunks, Chunk{
            Content: chunkText,
            Seq:     len(chunks),
            Start:   u.start + offset,
            End:     u.start + chunkEnd,
        })
        offset = chunkEnd
    }
    continue  // 这个 unit 处理完,跳过正常装箱
}
```

**切出来的是 chunk**(不走装箱,直接当结果)。

## 切法(两处一样)

1. **先按 7500 一刀切**
2. **往前回退最多 200 字**,找 `\n` 或空格,对齐到行/词边界
3. **找不到就硬切在 7500**(可能切词中间,但没办法)

```go
for i := chunkEnd - 1; i > offset && i > chunkEnd-200; i-- {
    if runes[i] == '\n' || runes[i] == ' ' {
        chunkEnd = i + 1
        break
    }
}
```

**为什么 200 字**:留 200 字的"对齐余地"。太短找不到边界(代码块里换行可能很稀疏),太长浪费 chunk 空间。200 是经验值。

---

## 是不是单独进一个 chunk?—— 不一定,看尾巴多长

**关键**:切出来的段是不是单独成 chunk,取决于 mergeUnits 的封口条件 `curLen + uLen > 512`。

| 段长度 | 装箱行为 | 结果 |
|--------|---------|------|
| 大段(接近 7500) | 必然单独一个 chunk(加任何 unit 都会更超 512) | 超 512 的 chunk |
| 尾巴 > 512 | 单独一个 chunk(加下个会更超) | 超 512 的 chunk |
| 尾巴 < 512,加下个 unit 会超 512 | 单独一个 chunk | < 512 的 chunk |
| 尾巴 < 512,加下个 unit 不超 512 | 跟下个 unit 合并 | 装到接近 512 再封口 |

**大段(接近 7500)必然单独一个 chunk**,因为 7500 > 512,加任何 unit 都会更超 512,必然封口。

**只有尾巴那段短的才可能跟其他合**。

---

## 具体例子:8500 字代码块

### Step 1:buildUnitsWithProtection 硬切

```
8500 字代码块 → maxProtectedSize=7500
  第一刀:offset=0, chunkEnd=7500
    回退找边界,假设在 7420 找到换行 → chunkEnd=7421
    → unit 1: 0~7421(7421 字)
  第二刀:offset=7421, chunkEnd=14921 > 8500 → chunkEnd=8500
    → unit 2: 7421~8500(1079 字)
  最终:2 个 unit(7421 字 + 1079 字)
```

### Step 2:mergeUnits 装箱

两个 unit 都 > 512:
```
unit 1(7421)→ 加任何 unit 都超 512 → chunk 1 单独,7421 字
unit 2(1079)→ 加下个 unit(假设 300 字)= 1379 > 512 → 封口 → chunk 2 单独,1079 字
```

**结果**:2 个 chunk,都超 512,但都 < 7500。**没有"跟其他合到 512"**。

## 尾巴可能跟其他合的例子:7800 字代码块

### Step 1:硬切

```
7800 字代码块 → maxProtectedSize=7500
  unit 1: 7421 字(回退对齐到换行)
  unit 2: 379 字(尾巴)
```

### Step 2:装箱

```
unit 1(7421)→ chunk 1 单独,7421 字
unit 2(379)→ current = [unit 2], curLen = 379
  看 unit 3(假设正文 200 字):379 + 200 = 579 > 512 → 封口
  → chunk 2 = unit 2 单独,379 字
current = [unit 3(200)], curLen = 200
  看 unit 4(假设 250 字):200 + 250 = 450 < 512 → 装,curLen = 450
  看 unit 5(假设 100 字):450 + 100 = 550 > 512 → 封口
  → chunk 3 = unit 3 + 4(450 字)
```

**结果**:
- chunk 1 = 7421 字(超 512)
- chunk 2 = 379 字(单独,< 512,因为加下个会超 512)
- chunk 3 = 450 字(装到接近 512)

## 为什么是 7500?

```go
const maxProtectedSize = 7500 // Maximum size for a protected unit (留余量给标题等)
```

**注释写得很清楚**:留余量给标题等。

- **embedding API 限制**:大部分 embedding 模型单次输入上限 8192 字(OpenAI text-embedding-3-small)
- **留 692 字余量**:给 ContextHeader(面包屑)+ 向量化拼接的标题 + overlap 留空间
- **7500 + 面包屑 200 + 标题 100 + overlap 80 ≈ 7880 < 8192** ✓

**所以 7500 不是技术限制,是 API 限制 + 留余量**。

---

## 为什么宁可硬切也不递归切

保护内容是"语义原子"(代码/表格/LaTeX),递归切会切在 `。` 或 `\n`,但代码里 `。` 可能是字符串字面量,`\n` 可能是注释里的换行,切了就破坏语义。

所以超 7500 时**降级为"按行/空格对齐硬切"**,不再按语义边界切。**找不到边界就硬切在 7500**,可能切词中间,但这是最后的兜底,总比超 8192 让 embedding API 报错强。

---

## 你应该带走的 5 件事

1. **7500 硬切有 2 个地方**:`buildUnitsWithProtection`(保护内容超 7500,切成多个 unit,后续走装箱)+ `mergeUnits`(兜底,单 unit 超 7500,切成多个 chunk,不走装箱)。

2. **切法**:先按 7500 一刀切,再往前回退最多 200 字找 `\n` 或空格对齐到行/词边界,找不到就硬切在 7500。

3. **是不是单独一个 chunk,看尾巴多长**:
   - **大段(接近 7500)必然单独一个 chunk**(加任何 unit 都会更超 512)
   - **尾巴 < 512 且加下个 unit 不超 512** → 跟下个 unit 合到 ~512
   - **尾巴 < 512 但加下个会超 512** → 单独一个 chunk

4. **7500 = embedding API 8192 限制 - 留余量**:给 ContextHeader + 标题 + overlap 留 692 字空间。

5. **为什么宁可硬切也不递归切**:保护内容是"语义原子",递归切会切在代码字符串字面量或注释换行上,破坏语义。硬切按行/空格对齐是最后兜底,总比超 8192 让 embedding API 报错强。
