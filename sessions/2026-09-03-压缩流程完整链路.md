## 关键发现(给 AI 自己看,防失忆)

### 压缩的两个时间点 + 两种手段

**两个时间点**:
1. 对话开始前(DB 读取 + 拼装):`LoadAgentHistory` 里 `CompactToolOutputForHistory` + `buildMessagesWithLLMContext` 里 `redactHistoryKBResults`
2. 每轮开头(loop 内):`manageContextWindow` 在 engine.go:599 调用

**两种手段**:
1. 压缩(CompactToolOutputForHistory / trimToolResults):按规则裁,丢内容保元信息
2. 摘要(Compaction):调 LLM 生成结构化摘要,保语义丢细节

### 阶段 0:DB 读取(LoadAgentHistory)

- `GetRecentMessagesBySession(sessionID, maxRounds*4)` 拉 raw rows
- 按 RequestID 配对 (user, assistant),过滤不完整 pair
- 取最近 maxRounds 轮,按 createdAt 排序
- 每个 pair 展开成消息序列
- **关键**:历史工具结果在这一步就压缩了(`CompactToolOutputForHistory`),不在 loop 里压

### 阶段 1:拼装(buildMessagesWithLLMContext)

- `[system, ...history, current_user]`
- history 里:KB 工具结果涂黑(`redactHistoryKBResults`),非 KB 工具结果已在 DB 读取时压缩
- current_user:`RenderUserTurnContent` 拼 `<runtime_context>` + `<must_use>` + query
- 跳过历史里的 system 消息(防注入)

### 阶段 2:ReAct Loop 每轮

**2.1 压缩检查**(engine.go:599):
```go
currentTokens := e.estimateCurrentTokens(*messagesPtr)
managed, changed := e.manageContextWindow(ctx, *messagesPtr, round, currentTokens)
```

**闸 1 Compaction**(主):
- 触发:`currentTokens > MaxContext - 16384`
- Prepare 找切点:`FindCutPoint` 从后往前累加,找最大保留尾部使 `<= keepRecentTokens`(默认 20000,上限 usable/4)
- 切点必须合法(tool result 不能当切点)
- split turn:切点落 turn 中间 → 前半段单独摘要
- buildSummary 调 LLM:
  - initial vs update 指令(有无 previousSummary)
  - Temperature 0.3,CacheRetention None(摘要禁缓存)
  - 重试 2 次,60s 超时
  - validateSummary 拒绝空响应 + length 截断
  - 失败 fallback rawArchive,degraded=true
- Apply 装配:`[system?, SummaryMessage, ...tail]`
- SummaryMessage 是 user 消息(`Role: "user", Kind: MessageKindCompactionSummary`),包在 `<summary>` 里
- minFreedFraction 5%:释放不够标记 `compactionExhaustedAt`,本轮不再试

**闸 2 trimToolResults**(兜底):
- Compaction 完还超阈值,或没东西可压
- 只裁 tool 结果,不动 assistant/user
- toolResultBudget = MaxContext / 5(8K~32K)
- 先全替成 marker,再从最新往最旧用剩余预算赎回完整 / head-tail 预览
- 保 ToolCalls 不动,保 OpenAI 配对不拆

**2.2 Think**:`callLLMWithRetry`

**2.3 Overflow 恢复**(engine.go:633):
- `responseHitContextLimit` 判断(finish=length 且 completion 远低于 budget)
- `forceCompaction`(reason=ReasonOverflow,不检查阈值)
- `overflowRecovered` 标志:每轮只恢复一次

**2.4 Analyze + Act/Observe**:
- `analyzeResponse` 判断停止(natural stop / content_filter / emptyContent)
- `appendToolResults` 追加 assistant + tool 消息
- 图片要求追加 user 消息(不动 system)

### 阶段 3:Loop 结束

- 触发:natural stop / stuck loop(连续 3 次同样内容)/ ctx.Err() / MaxIterations(新版默认 -1 无限)
- 持久化到 DB messages 表
- **没有额外压缩步骤**,压缩都在 loop 内
- 下一轮对话开始,LoadAgentHistory 重新从 DB 读,再走一遍持久化压缩

### 关键设计决策

| 决策 | 在哪 | 为啥 |
|---|---|---|
| 历史工具结果 DB 读取时就压缩 | LoadAgentHistory → CompactToolOutputForHistory | 一次压缩多次使用 |
| KB 工具结果额外涂黑 | redactHistoryKBResults | KB 可能被改,逼重新检索 |
| 摘要放 user 消息 | SummaryMessage | 不动 system 保 cache |
| 摘要用 Kind 标记 | MessageKindCompactionSummary | 下轮识别,增量更新 |
| 切点不参考当前轮 | FindCutPoint | turn 太大就 split,不豁免 |
| 摘要禁缓存 | CacheRetention: None | 中间态,下次用不上 |
| 5% 防无效摘要 | minFreedFraction | 防死循环 |
| overflow 每轮只恢复一次 | overflowRecovered | 恢复后还溢出 = 不是历史问题 |
| trimToolResults 只动 tool 结果 | trimToolResultsToBudget | 保配对不拆 |

### 跟旧版心智差异

- 旧版:4 道闸层层过滤
- 新版:两个时间点 + 两种手段(开始前压一次 + 每轮摘要一次 + 兜底裁一次)
