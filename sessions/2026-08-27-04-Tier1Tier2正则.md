## 我做了什么

1. 看了 `internal/infrastructure/chunker/patterns.go`(全文 98 行)—— 所有正则都在这
   - MarkdownHeadingPattern: `(?m)^(#{1,6})\s+(.+?)\s*#*\s*$`
   - GermanChapterPattern / EnglishChapterPattern / ChineseChapterPattern(中英德章节标记)
   - NumberedSectionPattern("1.1 Foo")
   - AllCapsHeadingPattern("INTRODUCTION")
   - VisualSeparatorPattern("---")
   - PageFooterPattern("Page X of Y")
   - FormFeedPattern(\f)
   - ExcessiveBlanksPattern(\n{3,})
   - 每个 pattern 带 priority(100到40),用于 Tier 2 同位置去重

2. 看了 `heading_splitter.go`(全文 343 行)—— Tier 1
   - splitByHeadingsImpl:用 DominantHeadingLevel 找主导层级 → findHeadingBoundaries 找切点 → 按 section 切
   - HeadingHierarchy 标题栈维护(stack[6]+depth),Observe 压栈清深层,BreadcrumbWithHashes 输出 "# XX\n## YY"
   - 超大 section 委托 SplitText 二次切,子 chunk 面包屑用 sectionBreadcrumbs 记录"子 chunk 起始位置对应的最深活跃标题"
   - coalesceTinyChunks 合并碎 chunk(FAQ 类文档防止校验失败)
   - 跳过 ``` 代码块里的伪标题
   - 降级条件:无标题/边界≤1个/校验不过

3. 看了 `heuristic_splitter.go`(全文 314 行)—— Tier 2

   - 8 个正则找切点,按 priority 排序后同位置去重
   - 超大 block 委托 SplitText 内切
   - applyOverlapAligned:overlap 对齐到最近边界/换行符
   - 降级条件:无边界/校验不过

## 关键发现(给 AI 自己看,防失忆)

- 两层都是正则,但用法不同:Tier1 用 1 个正则切 Markdown 标题;Tier2 用 8 个正则找各种结构信号当候选切点
- 所有正则都带 (?m) 多行模式,行首匹配
- 两层都跳过 ``` 代码块,防止代码注释里的 # 被误识别
- Tier 1 的 DominantHeadingLevel 算法:优先找"出现≥3次的最低层级",防止文档只有一个 H1 被切成"开头 vs 全文"
- Tier 2 的 priority 不影响切顺序(位置升序),只影响同位置多 pattern 命中时的去重保留
- HeadingHierarchy.stack[6] 固定数组,新同级标题会顶掉旧的深层标题
- 超大 section(Tier1)/超大 block(Tier2)都委托 SplitText 内切,三层协作
- coalesceTinyChunks 防止 FAQ 类碎 chunk 触发"chunk 太小"校验失败
