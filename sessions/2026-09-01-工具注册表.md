## 关键发现(给 AI 自己看,防失忆)

### ToolRegistry 核心结构

- **`ToolRegistry`**(registry.go:19):tools map + maxToolOutputSize(0 用默认 24000)
- **`types.Tool` 接口**:Name/Description/Parameters/Execute 4 方法
- **`BaseTool`**(tool.go:11):公共实现,具体工具嵌入 + 自己写 Execute

### `RegisterTool` first-wins 防劫持(registry.go:55)

- 同名工具先注册的留,后注册的拒
- 防 name collision attack(恶意插件冒充内置工具偷数据)
- 参考安全公告 GHSA-67q9-58vj-32qx

### `GetFunctionDefinitions` 排序保字节稳定(registry.go:92)

- Go map 迭代顺序故意随机化
- sort.Strings(names) 后按排序顺序遍历,保证序列化字节跨请求一致
- 字节级 prompt cache(Qwen explicit caching)需要字节级前缀匹配,不排序就 miss

### `ExecuteTool` 7 步(registry.go:112)

```
Step 1: PipelineInfo 日志(execute_start)
Step 2: GetTool(name) → 找不到返回错误 + toolErrorHint
Step 3: CastParams 类型转换(LLM 输出 "true" 转 true)
Step 4: ValidateParams 校验 → 失败返回错误 + toolErrorHint(返回 nil err,不是执行错误)
Step 5: 算输出预算(maxOutput,工具自定义 OutputLimitChars 只放大不缩小)
Step 6: tool.Execute(WithOutputBudget(ctx, maxOutput), args) 真正执行
Step 7: TruncateToolOutput 截断(rune count 不是 byte)+ 三级日志(Error/Warn/Info)
```

### CastParams 类型转换(param_cast.go:14)

- LLM 有时输出错误类型:"true" 而不是 true,"123" 而不是 123
- 按 JSON Schema 做安全转换:
  - 该 array 输出 string:JSON parse,失败就单字符串包成 []string
  - 该 boolean 输出 string:"true"/"false" 转 bool
  - 该 number 输出 string:strconv.ParseFloat
- schema nil 或解析失败返回原 args 不变

### ValidateParams 校验(param_validate.go:24)

- required:必填字段缺失
- type:JSON 类型匹配(string/number/integer/boolean/array/object)
- enum:值在允许集合
- minimum/maximum:数值范围
- minLength/maxLength:字符串长度
- 失败返回 ValidationError 列表,FormatValidationErrors 格式化
- **关键**:校验失败返回 nil error(不是执行错误),ToolResult.Success=false + 错误信息,让 runToolCall 不走错误路径,把错误给模型让模型换思路

### 输出预算 rune count 不是 byte(registry.go:164)

- `utf8.RuneCountInString(result.Output)` 不是 `len()`
- 中文 3 字节算 1 字符,用 byte 衡量 24000 字节只能放 8000 中文字
- 用 rune count 衡量 24000 runes 放 24000 中文字
- truncationMarkerReserve=200 留给截断标记("... [truncated to N chars]")

### outputLimitProvider 工具自定义预算(registry.go:27)

```go
type outputLimitProvider interface {
    OutputLimitChars(args json.RawMessage) int
}
```

- 工具可以实现这个接口自定义预算
- **只能放大不能缩小**(`if toolLimit > maxOutput`),防工具自设太小把输出截没了
- 用途:大数据工具(data_analysis / 图谱查询)需要更大输出

### toolErrorHint 常量(registry.go:16)

```go
const toolErrorHint = "\n\n[Analyze the error above and try a different approach.]"
```

- 三处加:工具找不到 / 参数校验失败 / 工具返回 Success=false
- 提示模型"分析上面的错误,换个思路",让模型下次试别的工具或参数

### 三类错误区分

| 错误类型 | 返回 | runToolCall 日志 |
|---|---|---|
| 工具找不到 | ToolResult{Success: false, Error: ...} + err | error 日志 |
| 参数校验失败 | ToolResult{Success: false, Error: ...} + nil err | warn 日志 |
| 工具执行失败 | ToolResult{Success: false, Error: ...} + nil err 或 err | 三级日志 |

执行错误(execErr != nil)是工具内部 panic 或 ctx 错;参数错误和工具返回失败是模型问题,返回 nil err 让 runToolCall 不走错误路径,把错误给模型让模型换思路。

### 完整例子流程(knowledge_search)

```
1. runToolCall Step 11 → toolRegistry.ExecuteTool(execCtx, "knowledge_search", args)
2. ToolRegistry.ExecuteTool:
   Step 1 PipelineInfo(execute_start)
   Step 2 GetTool("knowledge_search") → KnowledgeSearchTool 实例
   Step 3 CastParams(args, schema) 类型转换
   Step 4 ValidateParams(args, schema) 校验
   Step 5 maxOutput = 24000(或工具自定义放大)
   Step 6 tool.Execute(WithOutputBudget(ctx, 24000), args)
          - KnowledgeSearchTool.Execute 内部:解析参数 + 授权校验 + 检索 pipeline + 主动按预算截断
          - 返回 ToolResult{Success: true, Output: "...", Data: ...}
   Step 7 TruncateToolOutput(result.Output, 24000) 兜底截断
   Step 8 三级日志(PipelineInfo/Warn/Error)
3. 返回 ToolResult 给 runToolCall
4. runToolCall 装 ToolCall{Result: result} 推事件给前端
```

异常路径:
- 工具幻觉:Step 2 失败,返回错误 + toolErrorHint
- 参数错:Step 4 失败,返回 nil err + ToolResult.Success=false + toolErrorHint
- 工具失败:Step 6 返回 Success=false,加 toolErrorHint + PipelineWarn
