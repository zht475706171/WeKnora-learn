# Session 2026-08-28 · 保护机制 7500 硬切详解

## 用户原始需求

用户问:保护机制超过 7500 是怎么切割的?切成什么样?是单独进一个 chunk 吗?

然后追问:7500 一段不是远大于 512 吗?怎么还跟其他的一起装?是 7500 单独装一个大 chunk,切出来的多余部分再跟其他的装到 ~512 吗?

## 我做了什么

1. 查 splitter.go:308 的 maxProtectedSize=7500(buildUnitsWithProtection 硬切保护内容)
2. 查 splitter.go:401 的 absoluteMaxSize=7500(mergeUnits 兜底硬切超大 unit)
3. 确认两处切法一样:按 7500 一刀切 + 回退 200 找 \n 或空格对齐
4. 解释硬切结果:地方 1 切出来是 unit(走装箱),地方 2 切出来是 chunk(不走装箱)
5. 举例 8500 字代码块:切成 7421 + 1079 两个 unit,都 > 512,都单独成 chunk
6. 举例 7800 字代码块:切成 7421 + 379 两个 unit,尾巴 379 < 512 但加下个 200 = 579 > 512,所以也单独成 chunk
7. 解释 7500 = embedding API 8192 限制 - 留 692 字余量(给 ContextHeader + 标题 + overlap)
8. 解释为什么宁可硬切也不递归切:保护内容是语义原子,递归切会切在代码字符串字面量/注释换行上
9. 写笔记 notes/19-保护机制7500硬切详解.md

## 关键发现(给 AI 自己看,防失忆)

- 7500 出现在 2 个地方:
  - `buildUnitsWithProtection`(splitter.go:308):保护内容本身超 7500,切成多个 unit,后续走 mergeUnits 装箱
  - `mergeUnits`(splitter.go:401):兜底,单 unit 超 7500,切成多个 chunk,不走装箱
- 两处切法一样:按 7500 一刀切 + 回退最多 200 字找 \n 或空格对齐 + 找不到硬切在 7500
- 是不是单独一个 chunk,看尾巴多长:
  - 大段(接近 7500)必然单独一个 chunk(加任何 unit 都会更超 512)
  - 尾巴 > 512:单独一个 chunk
  - 尾巴 < 512 但加下个 unit 会超 512:单独一个 chunk
  - 尾巴 < 512 且加下个 unit 不超 512:跟下个 unit 合到 ~512
- 7500 = embedding API 8192 限制 - 留 692 字余量(给 ContextHeader + 标题 + overlap)
- 保护内容是"语义原子",递归切会切在代码字符串字面量/注释换行上,破坏语义,所以硬切按行/空格对齐
- 之前笔记 18 有个表述错:"7500 一段的 unit 会跟其他 unit 一起装到 ~512" → 错,7500 > 512 加任何 unit 都会更超,必然单独一个 chunk。只有尾巴那段短的才可能跟其他合。已在笔记 19 里讲清楚。
