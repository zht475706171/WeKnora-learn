## 关键发现(给 AI 自己看,防失忆)

- SelectStrategy 3 个条件:
  - Tier1: MdHeadingTotal>=3 && HeadingDensity>0.005 && DominantHeadingLevel>0
  - Tier2: HeuristicMarkerTotal>=5 || FormFeedCount>0 || 中英德章节>0
  - Tier3: 永远加
- 典型 chain:有 # 标题 → [T1,T2,T3];无 # 有结构 → [T2,T3];啥都没 → [T3]
- Split 是瀑布式:第一个通过 ValidateChunks 的就返回,不是 3 层都跑取最好
- ValidateChunks 4 判据:碎chunk多/最大太小/超2x/大文档1chunk
- "碎"定义:< 50 字(除最后一个)
- Tier 1 切点:level <= primaryLevel(主导层级及更粗的都切)
- Tier 1 coalesceTinyChunks 4 条件:sharedHeader!="" + 相邻 + curLen<target + 合并后<=chunkSize
- Tier 2 minChunkSize = ChunkSize/4,最小 50,是"封口的最小累积长度"
- Tier 3 SplitText 3 步:protectedSpans → buildUnitsWithProtection → mergeUnits
- Tier 3 7 种保护:LaTeX/图片/链接/表格头/表格行/代码块/行内代码
- Tier 3 递归:splitBySeparators 用 remaining(剩下的分隔符)内切,不全文重切
- Tier 3 表头追踪:headerTracker 检测表头开始/结束/空表头补全/列数不匹配结束,prepend 到新 chunk
- Tier 3 overlap:computeOverlap 3 级优先级(段落>行>句末),找不到边界不 overlap
- Tier 3 两个硬上限 7500:maxProtectedSize(保护单元)+ absoluteMaxSize(任何 chunk)
- 位置不变量 End-Start=runeCount(Content) 是所有设计的核心
- 向量化三段拼接:knowledge.Title + ContextHeader + Content(通过 buildKnowledgeIndexContent + EmbeddingContent)
