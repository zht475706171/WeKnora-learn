## 关键发现(给 AI 自己看,防失忆)

### Think 阶段三层调用链

- **`callLLMWithRetry`(think.go:378)** → **`streamThinkingToEventBus`(think.go:161)** → **`streamLLMToEventBus`(think.go:29)**
- 三层分工:外层管重试和降级,中坚层管分流,底层管流式细节
- 比喻:店长(callLLMWithRetry)/厨师长(streamThinkingToEventBus)/厨工(streamLLMToEventBus)

### `streamLLMToEventBus` 底层 4 步

- Step 1 装请求(120s 超时,`defaultLLMCallTimeout`):不是整个调用 120s,是 chunk 之间不能超过 120s
- Step 2 贴 prompt cache 指纹(`PromptPrefixFingerprint`):只覆盖稳定前导(system + tools schema),不覆盖对话历史
- Step 3 开流(`chatModel.ChatStream` 拿 stream channel)
- Step 4 消费流:`for chunk := range stream` 累加 Content,`StreamDecoder` 处理 UTF-8 多字节跨 chunk 拼接,`StreamError` 单独存不混进 Content,`Flush` 拼尾部残留

### `streamThinkingToEventBus` 中坚层 3 段

- 段 1 装配 ChatOptions:Temperature 0.7 / Tools 工具列表 / Thinking 思考开关 / ParallelToolCalls 并行工具调用(默认开,提速)
- 段 2 建 ThinkStreamSplitter + 3 个回调(emitThought 推思考 / closeThinking 关思考区块 / emitAnswer 推答案)
- 段 3 调 streamLLMToEventBus 执行
- chunk 分流 4 类:tool_call pending(累积不立刻推)/ thinking_tool(emitThought)/ reasoning_content(emitThought)/ plain content(emitAnswer)
- answer 乐观渲染(收到就推)+ 撤回机制(模型改主意要调工具时撤回 answer,用 AnswerStreamed/AnswerEventID 透传控制)

### `callLLMWithRetry` 外层 5 段

- 段 1 日志只详记最后 4 条(防日志爆炸)
- 段 2 SanitizeMessages 消毒(见下节)
- 段 3 调 streamThinkingToEventBus
- 段 4 失败判断 isTransientError(临时错误:网络抖动/429/500)+ 重试 maxLLMRetries=2 次线性退避(1s/2s,不是指数)
- 段 5 重试耗尽走优雅降级:有历史 tool 结果调 streamFinalAnswerToEventBus 合成答案返回 nil,nil;无历史 tool 结果返回 error

### SanitizeMessages 消毒机制(3 种动作)

源码:`tools/sanitize_messages.go:14`

**为什么需要**:OpenAI chat completion API 三个要求:
1. 不能有连续同角色消息(例外:tool 可以连续)
2. tool 角色消息必须能找到对应的 assistant tool_call(孤儿 tool result 报错)
3. 非 system 消息不能空内容

WeKnora messages 来源复杂(DB 历史 + 4 道闸处理),可能有边角问题,SanitizeMessages 兜底。

**动作 1:跳过空消息**(line 22-25)
- 条件:`Content == "" && Role != "system" && Role != "tool" && len(ToolCalls) == 0`
- system 空 / tool 空 / 带 tool_calls 的 assistant 空都不跳

**动作 2:合并连续同角色**(line 28-35)
- 条件:`len(result) > 0 && msg.Role != "tool" && prev.Role == msg.Role && prev.Role != "tool"`
- 合并方式:`result[len-1].Content += "\n\n" + msg.Content`,当前 msg 不入 result
- tool 角色不合并(多个 tool 结果连着正常)

**动作 3:孤儿 tool result 转成 system**(line 38-46)
- 条件:`msg.Role == "tool" && msg.ToolCallID != ""` 且 `!hasMatchingToolCall(messages[:i], msg.ToolCallID)`
- `hasMatchingToolCall`(line 55):从后往前扫所有 assistant 消息,看 ToolCalls 里有没有匹配 ID
- 转换:`Role = "system"`,Content = `"[Tool result for " + Name + "]: " + Content`,清 ToolCallID 和 Name
- 信息不丢,只是改角色

### 4 个举例(笔记 29 第五节详写)

1. **连续同角色合并**:两条 user 连着 → 合并成一条,Content 用 `\n\n` 拼
2. **孤儿 tool result 转 system**:tool 消息找不到对应 assistant tool_call → 转成 system,加前缀 `[Tool result for XXX]:`
3. **空消息跳过**:空 user 消息被跳过,空 system 留着
4. **完整复杂例子**:4 道闸处理后的产物(两条 system 连着 + 孤儿 tool + 空 user + 多 user 连着)→ 消毒后(两条 system 合并 + 孤儿转 system + 空 user 跳过)
